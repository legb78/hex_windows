A one-sentence dictation — the normal case — is inserted faster than you can move your hand back to the keyboard.

Why it is fast: Parakeet, not Whisper

Whisper was tried first, and dropped after measurement. It is an autoregressive encoder-decoder, so it pays a fixed cost of about 1.4 s per transcription however short the audio is. On a single sentence, that cost is paid in full.

Parakeet TDT v3 is a transducer and has no such bottleneck. Same recordings, Parakeet on CPU against Whisper on GPU, five-second clip: 2.29 s → 0.19 s.

It is the same engine Hex uses on macOS, and it recognises the spoken language on its own among 25 European languages — there is no language setting to get wrong.

Nothing leaves your machine

  • No cloud, no account, no API key. Once the model is downloaded, HexWin needs no network connection at all.
  • Your audio never touches the disk. The recording lives in memory and is gone the moment the transcription ends — there is no file to find, and nothing to clean up.
  • Dictations stay out of clipboard history. The text is handed over as a private transfer, so it never resurfaces in ⊞ Win + V, and whatever you had copied before is put back afterwards.
  • The keyboard hook watches for one chord and nothing else. It stores no keystrokes. The code is short and meant to be read: KeyboardHook.cs.

Two commands to start

Download the archive from the latest release, unzip it, then in PowerShell:

.\get-model.ps1     # about 480 MB, once
.\HexWin.exe

Nothing else to install — not even .NET, which is bundled inside the executable. A tray icon shows the state: grey while the model loads, blue when ready, red while recording, orange while transcribing.

What to expect, stated up front

  • SmartScreen will warn you once. The executable is not code-signed, so Windows shows “Windows protected your PC”. Click More info → Run anyway. A signing certificate costs several hundred euros a year; this project does not have one.
  • Some antivirus products flag it, because a global keyboard hook is a pattern they watch for. That hook is exactly what makes push-to-talk work from any window.
  • It cannot type into elevated windows unless it is elevated too. That is Windows UIPI isolation doing its job, not a bug.

How it is built

Two layers, kept apart on purpose. The Win32 shells — keyboard hook, audio capture, engine, text injection — wire up system APIs and decide nothing. Every decision lives in a pure layer tested without Windows: chord detection, keyboard auto-repeat, keys released out of order, a key left stuck after a session lock, a second dictation triggered while one is still running.
